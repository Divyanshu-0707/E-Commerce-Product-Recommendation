# AI E-Commerce Product Recommendation & Assistant

A workshop shopping assistant that combines hard catalog filters, semantic search, recommendation reasons, and an LLM assistant. The active catalog contains **600 fictional products across 12 categories**, with prices in INR.

## Features

- Natural-language search with category, budget, and supported attribute filters.
- Ranking using 80% semantic similarity and 20% keyword overlap, with keyword-only ranking if the embedding model is unavailable.
- Catalog-grounded matching before ranking: unsupported requests return no matches, and result lists are not padded with unrelated products.
- Reasons based on stored product attributes, plus side-by-side comparison.
- Catalog-grounded product Q&A, with optional Groq help for less direct wording, and an agent with search, comparison, and detail tools through Groq.
- Helpfulness feedback stored locally in `data/feedback.jsonl`.

Filters take effect when **Find recommendations** is clicked. Category phrases such as `phone`, `smartphones`, and `home kitchen` are recognized. Empty searches report the applied filters without relaxing them.

The optional **Budget (INR)** field sets a maximum price. Leave it blank for no price cap, including when the search text mentions a price. Use **Sort recommendations** to instantly order the returned matches by best match, price low to high, or price high to low. Sorting applies to the returned recommendations, not the entire catalog.

For API callers, `max_price: null` explicitly removes the budget constraint. Omitting `max_price` retains budget detection from the query; numeric values (including zero) apply an inclusive maximum. The AI assistant continues to recognize budgets written in its messages.

## Windows setup

Python 3.13 and Node.js 24 were used for local verification. Install Python and Node.js/npm, then open PowerShell at the repository root.

```powershell
py -3.13 -m venv backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

Start the backend in one terminal:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

From the repository root, start the frontend in a second terminal:

```powershell
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Open [the app](http://127.0.0.1:5173/). The first startup may download the embedding model. If it cannot load, catalog search still starts with keyword-only ranking. Keep ports 5173 and 8000: the frontend API address and backend browser-origin configuration use those ports.

Search and direct catalog-field questions do not require Groq credentials. The agent requires `GROQ_API_KEY`; Groq can also help map less direct product questions to stored fields. See [backend setup](backend/README.md). Local environments, secrets, generated embeddings, and feedback files are covered by `.gitignore`.

## API

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | API health |
| `GET /categories` | Available catalog categories |
| `GET /catalog-info` | Synthetic dataset metadata |
| `POST /recommend` | Ranked products and an optional no-result message |
| `POST /ask` | Catalog-field Q&A with optional Groq assistance |
| `POST /assistant` | Tool-using shopping agent through Groq |
| `POST /feedback` | Record recommendation helpfulness |

Interactive API documentation: [localhost:8000/docs](http://127.0.0.1:8000/docs).

## Catalog and limitations

The current data is generated by `scripts/generate_synthetic_demo_catalog.py`. It is fictional, not a source of real product claims or current prices. See [catalog documentation](docs/synthetic-catalog.md) for schema, generation commands, cache behavior, and the preserved legacy data. The project-generated catalog has not been licensed for redistribution; do not publicly redistribute it until the team approves reuse terms. The preserved laptop dataset has separate, unverified provenance and reuse rights.

- Embeddings are cached under `backend/.cache/`. If the model or a query embedding is unavailable, recommendations use keyword overlap across catalog text and attributes; this fallback does not understand synonyms as semantic search can.
- Direct product questions are answered from stored fields; unsupported or missing facts are reported as unavailable. Groq can identify relevant fields for less direct questions, and the returned answer is assembled from the validated catalog values.
- The shopping agent still requires Groq credentials.
- Supported category aliases and numeric phrases are limited; arbitrary language and conflicting inputs are not fully understood.
- Feedback is recorded but does not retrain recommendations. Matching conservatively requires the requested product words in catalog names, categories, brands, or attributes before semantic ranking. Common plurals and category aliases work; arbitrary synonyms, misspellings, and unsupported languages may return no matches. The supported soft use cases (programming, coding, music, work, daily use) affect ranking rather than proving suitability.
